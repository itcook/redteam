# redteam

模型无关的对抗式代码/文档评审工具。Rust 单 crate，产出 `redteam` 二进制 + Claude Code / Codex 插件。

## 它做什么

四阶段流水线，每阶段的产物都要能被审计：

1. **风险路由**：diff → 成区 → 四类信号（改动密度、外部 API 密集、关键模块、历史缺陷）→ H0 热区与风险档。
2. **疑点扫描**（scanner）：按组装包并行扇出，多模型「家族」各扫一遍，疑点取并集、agreement = 家族数。
   疑点是**指针不是结论**：一句话说清哪里可疑，必须带 quote（逐字原文，锚不上就丢）。
3. **深挖**（reviewer）：H0 热区、scanner 疑点、scanner needs 进同一条优先级队列，按 provider 门空位消费，
   预算随风险分。**finding 只由深挖产出**。
4. **流式复核**（verifier，缺省关）：对达到阻断阈值的 finding 再派一个异族模型复查。

## 设计原则（评审这个仓时请按它们判）

- **裸终端可用是底线**：功能尽量落进二进制，而不是宿主 prompt 编排。`--help` 是裸终端用户唯一的在场文档，
  与代码同权重维护。
- **降级不阻塞，但必须披露**：任何「本该做而没做」的事（预算截断、定位失败、读守卫拒绝、registry 缺失）
  都要能在报告 / md / 省略清单里看见。静默少报是本项目反复栽过的坑。
- **模型输出一律不可信**：文件路径、行号、quote 全部要在本地重新定位；模型给的 quote 锚不上就丢弃。
  注入外部文档（--spec、仓库简介）要过 denylist、PEM 私钥嗅探与结构中和。
- **观测先于判定**：新机制先只计数并披露，拿到真实分布再决定要不要改变产出。
- **同一件事不在两处各有一套行为**：两条路径做同一件事，必然有一条会被漏改——本仓已栽过多次。
