## 1. 问题重构

「慢且贵」不是一个问题：贵 = token 重发量；慢 = 串行往返次数。共享大部分杠杆但不全同
（缓存只治贵不治慢；减轮数两个都治）。

成本恒等式：**总成本 ≈ Σ(对话数 × 每对话轮数 × 每轮重发上下文)**。
实测（session 20260703-004708）：输入:输出 = 28.5:1 —— 钱没花在判断上，
花在反复把同样的事实搬进上下文。

现架构本质：**每个 cell 是无记忆的独立侦探**。代码库知识经最贵通道（LLM 多轮往返）
被获取 3模型 × B包 × R轮 次后全部丢弃。轮间浪费最大：r2 审的代码与 r1 几乎相同
（只多了 fix），却从零重来。

## 2. 核心设计原则

> **事实与判断分离。** 事实（代码是什么、谁调谁、diff 改了哪）是确定性的、共享无害、
> 应当只获取一次；判断（这段代码是否有问题）才是对抗价值所在、值得花 N 个模型的钱。
> 对抗独立性只需保护判断层——三个法官可以看同一份卷宗，只要卷宗是事实不是观点。
>
> **轮次间携带判决，只重审新证据。** 与 r8.1 quote 锚定 id、M3 partial/manifest、
> 台账判例、尾流守卫的既有演化方向同向——"自指尾流"问题本就是全量重审语义的病症。

一句话：**让二进制当侦探（一次），让模型只当法官（N 次）；轮与轮之间携带判决。**

## 3. 五支柱详设

### 支柱 1：轮次增量协议（杀 R×，最大单项杠杆，动协议语义）

**机制**：r1 全量深审；r2..rn 只审 ①上轮修复的 diff-delta ②其波及邻域
③声称已修复 finding 的定向复核；approve 前可选一次全量终扫兜底。
未动代码上的 findings 靠行无关 id 直接携带前轮 verdict，不重新推导。

**基建现成度（高）**：R8.1 quote 锚定 id（跨 fixup/位移稳定）、M3 partial/manifest
（表达"本轮只跑了哪些 cell"）、`--dismissed` 台账（跨轮判例）、尾流守卫（r5 approve
实证收敛）。缺的是：binary 侧「审指定 delta + 携带合并前轮 findings」的一等支持
（内置命令优先：增量逻辑落二进制，ship.md 只传轮次 base）。

**风险**：修复可能在未重审区域引入回归 → 邻域必审 + 终扫兜底；
「邻域」定义需要防糊（波及半径怎么算：同文件？import 邻接？——与支柱 2 的卷宗共享基建）。
携带 verdict 的 finding 若地基变了（quote 所在代码被 fix 间接改动）必须失效重审
——id 锚定失配即视为地基变动，天然可检。

**预期**：5 轮 17M → ~3.4M + 4×~1M ≈ 7M，**~2.5×**，延迟同降。

### 支柱 2：卷宗（dossier）——事实层只建一次（杀 M× 与轮数）

**机制**：fan-out 前，二进制为每 bundle 生成**纯事实卷宗**注入所有 cell：
diff hunk 所在完整块、changed symbol 仓内引用点（位置+签名+±3 行）、文件大纲。
模板从"你自己去读 callers/callees"改为"卷宗在此，不足再精读，核实义务不减"。

**生产技术 = 可插拔槽位**（架构不依赖）：
- 穷人版：词边界 grep 改动符号 + 缩进/括号取 enclosing block。零依赖，立即可做；
- scout 版：一个廉价模型跑一遍探索产卷宗（1 次对话换 M×R 次探索）；
- AST 版：tree-sitter tags（见姊妹篇；体积/工具链/ABI 成本在列）。
三档按语言混用，无 grammar 语言 grep 兜底，行为无损降级。

**设计红线（CRG 反教材内化）**：硬体积预算（≤8K tokens/bundle）+ 只装事实不装观点
+ 截断必标注。判断独立性用 A/B 监控（finding 重合度/agreement 分布不应显著收窄）。

**预期**：cell 轮数 12 → 3-6，二次方高次项与串行延迟同砍，**~2-2.5×**，与支柱 1 正交相乘。

### 支柱 3：对话内上下文治理（杀二次方尾巴，与缓存有对冲）

**机制**：
- 陈旧结果驱逐：超过 k 轮的旧 tool result 换存根（"[已读 X 全文，需回看请重读]"），
  平均每份 64KB 结果从重复付费 ~6 次降到 ~2 次；要回看再读，executor 免费、重发收费。
- 强制分段读：大文件不带 range 的 read_file 返回"大纲+请指定行范围"，
  把 64KB 整读膨胀单元改成 KB 级窗口读。

**⚠️ 与 L1 缓存的对冲**：驱逐会改写历史 → 从改写点起 provider 前缀缓存全失效。
若缓存生效（读 0.1×），二次方重发已近似线性，驱逐省的钱有限还砸缓存；
若 provider 不支持缓存（中转站），驱逐价值大。**决策依赖 P0 缓存观测数据**，
在此之前不动。分段读无此冲突，可先行。

### 支柱 4：预算分层——成本从事故变契约（产品旋钮，后置）

确定性风险信号（diff 体积/敏感路径/测试缺口）+ 可选廉价 triage 给 bundle 分级：
高风险 3 模型 replicate、低风险 1-2 模型——覆盖不减、火力按风险配置。
refute 提效：finding 契约加 `evidence: [{file, lines}]`，refute prompt 预注入摘录，
skeptic 从 13 轮盲查变 1-3 轮定向复核。对外 `--budget` 档位（逻辑在二进制）。
诚实的成本-质量旋钮而非免费午餐，故后置。

### 支柱 5：成本可观测性（一切 A/B 的前提，并入缓存 session）

per-cell 轮数、explore/refute 分账、cached tokens、每轮成本估算进 result.json 与 status。
**→ cached 观测 + Anthropic cache_control 已随 L1 实施（dev d579948，另见 9c74744 cell
运行学）**；支柱 3（驱逐）×缓存对冲的决策数据自此开始积累。

## 4. 组合账与相互作用

支柱 1 (~2.5×) × 支柱 2 (~2-2.5×) × 支柱 3 (~1.5×，视缓存而定) ≈ **一个数量级**：
17M → 2-3M tokens，75min → 15-25min，不动对抗语义；支柱 4 额外旋钮；缓存账单侧再乘。
验收沿 M6 batch1 方法论：input_tokens/耗时显著降 + 四判据不回退
（真 finding 不丢、误报不增、id 稳定、reappeared 零）。

相互作用矩阵：
- 支柱 1 × 2：正交相乘；且支柱 1 的"波及邻域"计算可复用支柱 2 的引用索引。
- 支柱 3(驱逐) × L1 缓存：**对冲**，等 P0 数据再决策。
- 支柱 2 × L1：基本正交（不同 provider 缓存不互通；卷宗稳定前缀略利缓存）。
- 支柱 4 × 1/2：独立叠加。

## 5. 不做清单

- 不砍模型数/轮次作为首选（卖产品换钱）；
- 不上 embeddings/RAG/向量库（非确定性 + 索引运维，与确定性内核相悖；
  卷宗场景精确引用胜过语义相似）;
- 不做宿主侧编排（M9 立场不动，全部落二进制）；
- 不追求精确调用图（卷宗=定位提示，标注 heuristic，判断归模型）。
